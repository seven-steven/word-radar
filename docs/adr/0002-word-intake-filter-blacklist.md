# 收词过滤:缩略词黑名单+缩合形式拦截(否决词典白名单、词频截断与双表制)

采集需要拦掉缩略/截短词(md、doc、stat)与缩合形式(you've、aren't),硬约束是正式冷僻词(serendipity)绝不误杀——而 doc、stat 在任何语料里的词频都**高于** serendipity,词频维度上「拦截目标」与「保护目标」不可分。因此收词过滤采用两个判据:其一,内置**缩略词黑名单**——命中即静默丢弃(摘要只报数量),未命中全放行;其二,**缩合形式拦截**——剥离所有格 `'s` 后仍含撇号(you've、aren't、o'clock)即丢弃,不展开为成分词。黑名单在构建期从 Wiktionary 的 clipping/abbreviation/initialism 标签词条提取,辅以手工 initialism 种子表(md 的英文词条是埃及语转写 mdw 的变体,标签通道抓不到它)。验收线:md/doc/stat/you've/aren't 命中,serendipity/serendipity's/dog's/monorepo 放行(2026-09-07 grilling 定稿)。

## Considered Options

- **综合词典白名单**(不在表内即丢):doc、stat 是词典收录的真词,拦不住用户点名的目标;monorepo 等新词/行话反被误杀,还得为误杀加「可见可捞回」UI。两个方向都不占优,否。
- **学习词典小词表白名单**(Oxford/NGSL 3-5k 量级):serendipity 不在表内,恰好误杀产品最该收的词,否。
- **词频截断**(低频即丢):方向反了——拦截目标(doc/stat)比保护目标(serendipity)更高频,否。
- **无元音短串盲启发式**(拦 md 这类 initialism):my/by/why 全是无元音短串,盲杀它们违反「高频简单词不过滤」的共识(简单词入一次库、背一次即无害),否;initialism 改走手工种子表。
- **黑白双表制**(白名单确认正式词+黑名单拦缩写+中间地带进待确认批次默认不勾):最周全但机制最重,UI 要加分组,超出「背一次就行」的轻量取向,否。
- **黑名单+缩合拦截双判据**:黑名单零误杀正式词,漏网代价仅是不在表内的行话截短(conv、repo)通过;缩合形式以撇号判据精确拦截。选此。

## Consequences

- 黑名单是构建期生成的静态资源随 core 分发,非运行时下载;词形还原后按小写 lemma 匹配(docs→doc 命中)。
- 词表内容用户不可增删,只有「过滤缩略词」「过滤缩合形式」两个开关(默认全开)——避免误删内置条目导致过滤静默退化。
- 过滤加在 core 提取层,网页采集/上传文件/CLI extract 统一生效;CSV 导入不经提取管线,天然豁免。
- 所有格剥离(dog's→dog)属归一化不属过滤,不受开关控制:罕见词以所有格形态出现时不漏收。
- 简单高频词(a、the)明确不过滤:一次性入库、推送一次即永为非新词,为其建词频机制不值得。
