# 提高 minimum_chrome_version 到 127

v1.1 右键菜单(「采集当前页」「上传文件」)需要 `chrome.action.openPopup()`,而该 API 到 Chrome 127 才对所有扩展开放——118–126 仅 Canary/企业策略安装的扩展可用。为此把扩展的 `minimum_chrome_version` 从 114 抬到 127(`packages/extension/src/manifest.json`),换取右键菜单入口的单一实现。114 是 2023-05 的版本线,沿用至今只是初始默认,并非有意的兼容承诺。

## Considered Options

- **保 114 + feature-detect 静默降级**:检测不到 `openPopup` 就不注册右键菜单,低版本用户点菜单无反应,还得引导「请点工具栏图标」;降级分支需按版本矩阵覆盖测试,长期维护两套行为。否。
- **保 114 + 扩展 tab 页 fallback**:低版本右键改为打开扩展自有 tab 页承载同款界面,要长期维护 popup 与 tab 两套壳(布局/生命周期/消息通道皆不同),成本最高。否。
- **抬到 127**:接受。

## Consequences

- 放弃 Chrome 114–126 存量用户:2026 年占比可忽略,以企业长支持环境为主;而企业环境恰是 118–126 能用 `openPopup` 的例外,实际损失进一步缩小。
- 采集/推送等核心能力不依赖 127 才有的 API,受影响用户表现为「装不上新版」而非功能残缺;真正的损失只是右键菜单这一个入口。
- 右键菜单一条代码路径,零降级分支。
